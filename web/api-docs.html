Security Layer

Authentication & Access Control (api/auth.py)

NexChecker enforces four distinct authentication modes depending on endpoint scope. Never share your BOT_TOKEN or API_ACCESS_KEY in client-side code.

Mechanism Header / Param Used By Validation Rule
Dedicated API Key X-API-Key or Authorization: Bearer <key> /api/v1/purchase, /api/purchase Constant-time hmac.compare_digest against API_ACCESS_KEY / NEXCHECKER_API_KEY (open if env unset).
NexNum Account Key X-NexNum-Key or JSON api_key /api/v1/purchase, /api/purchase Forwarded directly to NexNum API so purchases & refunds occur on caller's NexNum balance.
Telegram WebApp HMAC X-Telegram-Init-Data or ?init_data= /api/checker/*, /api/auth/me, /api/history* HMAC-SHA256 using secret HMAC("WebAppData", BOT_TOKEN); max age 86400s (-120s skew).
Guest / Soft Identity X-Guest-ID or cookie nex_guest_id DELETE /api/history/{record_id} Sanitized [a-zA-Z0-9_-] fallback to client IP (X-Forwarded-For / X-Real-IP).
Webhook Secret X-Telegram-Bot-Api-Secret-Token /bot/webhook, /api/bot/webhook Exact string match against WEBHOOK_SECRET env var when configured.
Test Bypass Mode
When ENVIRONMENT=testing is set on the server or X-Test-Bypass: 1 is passed while running tests, enforce_authenticated_identity injects a synthetic test identity (tg_99999999). Do not enable ENVIRONMENT=testing in production.

Purchase & NexNum Integration

        
Targeted Virtual Number Purchase


        

          

            

              POST
              /api/v1/purchase
              Alias: /api/purchase
              X-API-Key + X-NexNum-Key
            

            
          


          

            

              Acquires virtual numbers from NexNum on the caller's own NexNum balance, verifies each acquired number silently against the target platform, automatically queues non-matching numbers for deferred cancellation/refund, and returns the exact NexNum order_id upon matching target_status.
            


            
Request Parameters

            

              

                
FieldTypeDefaultDescription

                
                  
platform Requiredstring"zomato"Target checker slug: zomato, flipkart, myntra, meesho, amazon, swiggy, bigbasket, zepto.

                  
target_status Optionalstring"NOT_REGISTERED"Filter condition: NOT_REGISTERED (fresh) or REGISTERED (existing account).

                  
service_code OptionalstringPlatform mapNexNum service code override (defaults: zomato=dy, flipkart=xt, myntra=nl, bigbasket=bb, amazon=am, swiggy=sw, meesho=me, zepto=zp).

                  
country_code Optionalstring"22"NexNum numeric country code ("22" = India).

                  
max_attempts Optionalinteger5Maximum acquire-and-check cycles before aborting. Validated range: 1 to 20.

                  
api_key Cond.stringnullCaller's NexNum API key. May alternatively be passed via X-NexNum-Key header (header takes precedence).

                
              

            


            

              
Loop Termination & Inconclusive Safety Rules

              1. Fatal Account Errors: BAD_KEY (HTTP 400), NO_BALANCE / BANNED (HTTP 402) stop immediately.

              2. Consecutive Inconclusive Break: If a checker returns ERROR, TIMEOUT, UNKNOWN, or DISABLED, the number is cancelled/queued and retried once. If the next consecutive check is also inconclusive (consecutive >= 2), the loop aborts immediately with HTTP 422 CHECKER_INCONCLUSIVE.

              3. Nginx Proxy Timeout: Keep max_attempts modest behind Nginx (proxy_read_timeout 60s).

Deferred Cancel Queue Lifecycle (api/cancel_queue.py)

        

          NexNum rejects immediate cancellations (setStatus=8) during the initial ~60–120 second window with EARLY_CANCEL_DENIED. CancelQueueManager starts on FastAPI lifespan startup and guarantees credit recovery:
        

        

          

            
ParameterValueBehavior

            
              
CANCEL_MIN_AGE60sMinimum age in queue before background worker attempts cancellation.

              
CANCEL_POLL_SECS30sBackground sweep interval firing matured cancellations concurrently via asyncio.gather.

              
max_retry4 cyclesMaximum worker retries (~2 minutes) before dropping un-cancellable items.

              
CANCEL_TERMINALBAD_STATUS, BAD_KEY, BANNED, ACCESS_ACTIVATIONTerminal responses immediately remove the order from the queue without further retries.

            
          

        

      


      
      

        
Silent Registration Checkers

        
Verification Endpoints & Platform Matrix


        

          

            

              POST
              /api/checker/phone
              Alias: /api/check/phone
              Telegram HMAC Auth
            

            
          

          

            

              Checks a single 10-digit Indian mobile number on a specified platform (or "all" to query all 8 engines sequentially). Automatically strips leading 91, records latency and stats to universal_stats.json, and saves the result to the caller's server history.
            

            

              
Request & Response Schema

              
// Request
{
  "phone": "9876543210",          // or "target_phone"
  "platform": "zomato",           // zomato|flipkart|meesho|myntra|swiggy|amazon|bigbasket|zepto|all
  "checker_phone": null           // optional caller context
}

// Response (200 OK)
{
  "success": true,
  "phone": "9876543210",
  "platform": "zomato",
  "registered": false,
  "fresh": true,
  "status": "NOT_REGISTERED",
  "universal_total_checks": 112,
  "platform_total_checks": 54
}

            

          

        


        

          

            

              POST
              /api/checker/batch
              Alias: /api/check/batch
              Telegram HMAC Auth
            

            
          

          

            

              Runs concurrent checks on the backend via asyncio.gather for up to 50 mobile numbers on a single platform and persists each record to caller history.

Authentication & History Endpoints


        

          

            

              GET
              /api/auth/verify
              Public Verification
            

            
          

          

            
Validates Telegram WebApp initData passed via X-Telegram-Init-Data header or ?init_data= query parameter. Returns authenticated: true + parsed user object when status is OK, or granular reason (MISSING, EXPIRED, TAMPERED, MISSING_HASH, MISSING_DATE, INVALID_DATE, SERVER_TOKEN_MISSING).

          

        


        

          

            

              GET
              /api/auth/me
              Telegram HMAC Auth
            

            
          

          

            
Returns verified UserIdentity metadata (user_id, auth_type, telegram_id, username, first_name, ip_address).

          

        


        

          

            

              GET
              /api/history?limit=50
              Telegram HMAC Auth
            

            
          

          

            
Fetches up to 100 latest per-user check records stored atomically in data/server_history/users/{user_id}.json.

              /api/history/clear
              Telegram HMAC Auth

              Telegram / Guest Identity

Client Architecture

        
Frontend WebApp Architecture (web/)

        

          Built with zero external JS framework dependencies for sub-second load inside Telegram WebView and desktop browsers.
        


        

          

            
File / ComponentResponsibilities & Mechanics

            
              
web/index.htmlApp shell (max-width 520px), #securityGate overlay for unauthenticated visitors, sticky header + 6 active platform carousel chips, single check card, radar animation, flip result card, batch scanner, pull-to-refresh history, and bottom navigation.

              
web/style.cssDark-first CSS variables mutated dynamically via <html data-brand="..."> for 8 brand themes (zomato, flipkart, meesho, bigbasket, myntra, swiggy, zepto, amazon), spring animations, radar pulses, and responsive layout.

Bot Worker & Persistence

        
NexBot Core & Hierarchical Storage

        

          

            
ModuleKey Capabilities

            
              
NexBot/core/nexnum_api.pyAsync NexNumClient using Accept: application/json content negotiation + legacy plain-wire fallback parser (ACCESS_NUMBER:...), 3x backoff retries for getBalance, getNumber, getStatus, setStatus.

              
NexBot/core/sms_poller.pyBackground OTP poller firing every 5s up to 19 min; deduplicates by SMS id (supports multi-OTP on same code); formats IST timestamps; native Telegram CopyTextButton; auto-cancels at 10 min if no SMS arrives.

              
NexBot/core/user_store.pyPer-user async locks writing atomic files under NexBot/data/users/{tg_id}/info.json and {order_id}.json for collision-free concurrent multi-platform sessions.

              
api/history_manager.pyServer history isolated at data/server_history/users/{user_id}.json (retaining latest 100 entries) plus global aggregate registry users_index.json.
