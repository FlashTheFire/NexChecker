Security Layer

Authentication & Access Control (api/auth.py)

NexChecker enforces four distinct authentication modes depending on endpoint scope. Never share your BOT_TOKEN or API_ACCESS_KEY in client-side code.

Mechanism Header / Param Used By Validation Rule
Dedicated API Key X-API-Key or Authorization: Bearer <key> /api/v1/purchase, /api/purchase Constant-time hmac.compare_digest against API_ACCESS_KEY / NEXCHECKER_API_KEY (open if env unset).
NexNum Account Key X-NexNum-Key or JSON api_key /api/v1/purchase, /api/purchase Forwarded directly to NexNum API so purchases & refunds occur on caller's NexNum balance.
Telegram WebApp HMAC X-Telegram-Init-Data or ?init_data= /api/checker/*, /api/auth/me, /api/history* HMAC-SHA256 using secret HMAC("WebAppData", BOT_TOKEN); max age 86400s (-120s skew).
Guest / Soft Identity X-Guest-ID or cookie nex_guest_id DELETE /api/history/{record_id} Sanitized [a-zA-Z0-9_-] fallback to client IP (X-Forwarded-For / X-Real-IP).
Webhook Secret X-Telegram-Bot-Api-Secret-Token /bot/webhook, /api/bot/webhook Exact string match against WEBHOOK_SECRET env var when configured.
Test Bypass Mode
When ENVIRONMENT=testing is set on the server or X-Test-Bypass: 1 is passed while running tests, enforce_authenticated_identity injects a synthetic test identity (tg_99999999). Do not enable ENVIRONMENT=testing in production.
Purchase & NexNum Integration

Targeted Virtual Number Purchase

POST /api/v1/purchase Alias: /api/purchase X-API-Key + X-NexNum-Key

Acquires virtual numbers from NexNum on the caller's own NexNum balance, verifies each acquired number silently against the target platform, automatically queues non-matching numbers for deferred cancellation/refund, and returns the exact NexNum order_id upon matching target_status.

Loop Termination & Inconclusive Safety Rules

              1. Fatal Account Errors: BAD_KEY (HTTP 400), NO_BALANCE / BANNED (HTTP 402) stop immediately.

              2. Consecutive Inconclusive Break: If a checker returns ERROR, TIMEOUT, UNKNOWN, or DISABLED, the number is cancelled/queued and retried once. If the next consecutive check is also inconclusive (consecutive >= 2), the loop aborts immediately with HTTP 422 CHECKER_INCONCLUSIVE.

              3. Nginx Proxy Timeout: Keep max_attempts modest behind Nginx (proxy_read_timeout 60s).
